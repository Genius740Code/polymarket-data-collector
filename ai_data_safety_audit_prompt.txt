2. SAVE PATH — is collected data actually persisted? (critical)
   - Trace: WS frame -> writer.append -> WAL-before-buffer (parquet_writer.py) ->
     flush (interval/row-count) -> atomic tmp+rename. Flag any append path that skips WAL.
   - grep: WAL-failed, DROP bucket, write_failed, close_flush_failed, flush_short,
     wal_replay_flush_short. Each DROP must be counted + emit collector_events.
     Silent drops, drops without counters, WAL truncated before flush success -> CRITICAL.
   - Verify startup WAL replay replays AND flushes AND warns on replay/flush mismatch.
   - Verify ParquetWriter.close() never reports clean shutdown with rows unflushed.

3. STALE / LIVE LABELING (critical)
   - Snapshots on 500ms UTC grid floor(unix_ms/500)*500 (book.py). Flag drift/un aligned schedulers.
   - book_state=='live' ONLY when WS connected for that asset; else 'stale'/'resyncing'.
     Flag: live-labeled rows during disconnect (check subscribed_once/connection-state bugs).
   - Null-vs-zero (book.py): empty side = null price AND null size, never 0. Flag violations.
   - book_crossed rate, L2 sort order, depth aggregates vs own-side best — flag anomalies,
     but NEVER "fix" by deleting stale rows.

4. MISSING DATA / GAP HONESTY (critical)
   - High-stale day (>30%) with NO resync_episodes = silent failure -> CRITICAL.
   - Every resync_episodes row must have gap_duration_ms populated.
   - Clean-view parity: every (date,asset) in book_snapshots_500ms needs a partition in
     book_snapshots_clean (rebuild, never delete source).
   - Chainlink/settlement: unknown is honest; inferred must be flagged fee_is_estimated/
     inferred_nearest — never invented on-chain tx/price.
   - book_events: price_change rows with old==new on BOTH bid+ask at >5% = fake generator -> CRITICAL.

5. DISK-FULL RESILIENCE (the 2026-09-22 class — critical)
   - Slowest-lane deadlock: does ANY emergency path free bytes when a lane never uploads?
     cleanup_local_data fail-closed on missing lane is CORRECT for hive; verify the
     emergency path still reclaims staging (rebuildable) so 0-file prunes don't = death.
   - 0-byte moves: any "prune" that MOVEs within the same filesystem without a bounded
     reap frees 0B — verify reap is called on the emergency path and capped
     (quarantine_retention_hours / quarantine_max_bytes).
   - Throttle vs fill rate: emergency throttle interval vs observed flush growth/30s.
     A 30-min throttle against MBs/minute fill = deferred death. Verify critical-tier
     bypass (e.g. free <256MB runs unthrottled).
   - Growth accounting: lanes × assets × 500ms + clean-view duplicate + per-lane staging
     copies + quarantine + WAL + logs vs box size. Verify retention_cadence_check math
     (lanes × upload_interval vs local_retention_hours, 2x headroom) AND that it accounts
     for build overruns/failures, not just the happy path.
   - Scope mismatch: free-space check watches the whole filesystem but reclaim only
     touches data_dir — flag unmonitored external hogs (opencode.db, .venv, /tmp, logs/)
     with no startup warning or log rotation.
   - Config vs reality: timeframes list vs comments (5-lane list with 2-lane comment =
     incident). Retention shorter than a lane's market lifetime (e.g. 4h retention with
     1d lane) means that lane's files are NEVER prunable — flag.
   - Restart storms: repeated restarts replaying WAL + rebuilding all lane staging
     simultaneously while disk is low. Verify backoff / single-lane-at-a-time behavior.

6. ERROR SWALLOWING
